# What we took from Meta's agent workshops, and where it lives in Pheri

Each lesson below comes from Aditi's notes from the Agents 101 and Agents 102 workshops (hackathon week,
Oct 2026). For each one: where it is in the code, and the test that fails if it stops being true. Tests are in
`api/tests/` and run with `cd api && python -m pytest`. Where Pheri falls short, the row says so.

## Agents 101

| Lesson | In Pheri | Proved by |
|---|---|---|
| **Plan before code** | Two places. The build itself: every feature starts as a written plan (CLAUDE.md "Build plan" and Status; the week's plan with hours and costs). At run time: the agent reads before it acts. `decide.SYSTEM` makes `get_profile` and `list_allowed_actions` come before any action, and `check_rules` dry-runs the plan before the message is written. | `test_decide.py::test_the_turn_log_shows_the_agents_loop`, `test_decide.py::test_maya_discount_is_blocked_in_the_loop_and_she_gets_help` |
| **The system prompt (behaviour) is separate from the objective (task)** | `decide.SYSTEM` says how Pheri works and holds no customer, business or date. The task (customer, business, today) is the first user turn, the "brief" in the trace. The guard is built the same way (`guard.SYSTEM` plus the customer's text as escaped JSON data), and so is the rule compiler (the owner's words go in as data). | `test_decide.py::test_the_system_prompt_is_behaviour_and_the_task_is_the_brief`, `test_rules.py::test_owner_words_go_to_the_model_as_data` |
| **A checklist, and records** | The checklist is `verify.CODE_CHECKS` (13 named checks), run on every draft, with each result stored on the action. The records are an append-only audit log for every rule, approval, send, override and discarded tool call (`store.audit`; in Postgres, triggers forbid UPDATE, DELETE and TRUNCATE in `db/schema.sql`). Each live run is also saved (`runlog.save_run`). | `test_schema.py::test_audit_log_triggers_block_rewrites`, `test_autonomy.py::test_set_mode_is_validated_and_audited`, `test_autonomy.py::test_an_owner_can_send_a_soft_failure_anyway_and_the_log_says_who_when_what_and_the_text` |
| **A turn budget** | `decide.MAX_TURNS = 5` (tool rounds plus the answer; live decisions took 3 or 4), one `NUDGE` when the model answers in plain text, and `PHERI_VERIFY_MAX_ATTEMPTS = 3` drafts. Then the owner. | `test_decide.py::test_endless_tool_calls_stop_at_the_turn_limit`, `test_decide.py::test_plain_text_gets_one_nudge`, `test_verify.py::test_the_number_of_drafts_is_a_setting_and_then_a_person_takes_over` |
| **A step-by-step trace view** | `Outcome.turn_log` (what was sent and what came back, turn by turn), served at `GET /businesses/{b}/customers/{key}/trace`. The web page `web/app/[business]/customers/[key]/trace` shows every draft, which layer caught it, and the reasons sent back. | `test_decide.py::test_the_turn_log_shows_the_agents_loop`, `test_app.py::test_the_stored_decision_and_its_trace` |
| **Model output is unverified: add guardrails** | Code decides, models explain. Facts are counted in code (`profile.compute_facts`); evidence is picked by id and the values attached by code (`decide.decision_schema`); the owner's rules are pure code (`rules.check`); every draft is checked (`verify.verify_draft`); every reply goes through the code screen first (`guard.screen`). | `test_profile.py::test_facts_come_from_code_not_the_model`, `test_decide.py::test_the_schema_only_offers_this_customers_facts_and_quotes`, `test_guard.py::test_screen_sees_through_simple_disguises` |

## Agents 102

| Lesson | In Pheri | Proved by |
|---|---|---|
| **Verification is mandatory and inside the action (submit/send), never a tool the agent chooses** | `autonomy.submit()` calls `verify_draft()` itself and stores the result with a hash of the exact payload. `autonomy._execute()` refuses any customer-facing action whose stored verification did not pass for that payload. `verify_draft` is not one of the model's tools. | `test_verify.py::test_the_model_cannot_call_verification_or_send_anything_itself`, `test_verify.py::test_no_path_sends_a_message_without_passing_verification`, `test_autonomy.py::test_a_message_changed_after_verification_is_refused_at_the_send_step` |
| **Deterministic checks first (completeness, format, content rules such as no invented numbers), then LLM-as-judge for claim correctness** | `verify_draft` runs the 16 code checks (schema, evidence, invented numbers, dates and plan names, pronouns, links, money, and more), then the judge (Muse Spark Open), claim by claim, against only the facts the draft cites. | `test_verify.py::test_the_judge_is_asked_only_after_every_code_check_passes`, `test_verify.py::test_the_judge_gets_claims_and_only_the_cited_facts`, `test_verify.py::test_a_cited_facts_window_is_backed_but_no_other_number` |
| **Verify intermediate artifacts (the plan) against ground truth, with a tunable threshold** | The middle step: before a message is written, code scores its own journey stage and the chosen plan against the labelled truth set (`data/synth/*/_truth.json`, plans from the twin's hidden table). The bar is per business and per kind of action (`verify.THRESHOLDS`). | `test_verify.py::test_the_middle_step_bar_is_per_business_and_per_kind_of_action`, `test_verify.py::test_the_plans_in_the_truth_set_come_from_the_twins_hidden_table` |
| **Feed failures back, with a retry cap (3), then escalate to a human** | Failed checks go back to the model as the next turn of the same conversation (`verify.feedback`), for at most 3 drafts. Then the draft goes to the owner's queue with the reasons, and it is never sent on its own. | `test_verify.py::test_a_claim_the_judge_rejects_goes_back_and_the_next_draft_passes`, `test_verify.py::test_the_number_of_drafts_is_a_setting_and_then_a_person_takes_over`, `test_autonomy.py::test_a_hard_failure_goes_to_the_owner_with_the_reasons_and_no_one_can_send_it` |
| **Thresholds set by stakes (near 100% for money)** | `THRESHOLDS`: money actions (discount, upgrade, subscription) need 100%, nudges 80%. In Birgunj, code's "gone quiet" is right 97% of the time, so a goodwill discount is refused and a check-in goes instead. | `test_decide.py::test_money_needs_a_stage_code_is_sure_of_so_an_unhappy_quiet_customer_gets_a_nudge`, `test_decide.py::test_without_the_rule_the_middle_step_still_refuses_a_discount_for_a_stuck_customer` |
| **A tool allowlist: discard unknown or self-built tools** | `decide.ALLOWED_TOOLS` lists three tools. Any other call (`issue_refund`, `verify_draft`, `send_message`) is discarded, never run, audited as `tool_call_discarded`, and fails the hard `tools` check. | `test_evals.py::test_three_attacks_try_to_make_pheri_call_a_tool_it_does_not_have`, `test_decide.py::test_bad_tool_arguments_and_unknown_tools_return_errors_to_the_model` |
| **Delayed outcomes: use intermediate milestones** | `twin.MILESTONES` (Birgunj): a reply on day 1, an order on day 3, a reorder by day 30. `twin.MilestoneThompson` learns from a reply as provisional evidence and replaces it with the real order. Each milestone is credited to the decision that caused it (`twin.Event`). | `test_twin_milestones.py::test_replies_lead_first_and_orders_correct_them`, `test_twin_milestones.py::test_every_milestone_is_credited_to_the_decision_that_caused_it_on_its_day`, `test_twin_milestones.py::test_correcting_with_orders_beats_learning_from_replies` |
| **Block only on checks that later steps depend on** | Hard checks (rules, schema, evidence, facts, pronouns, links, money, tools) block, and nobody can override them. Soft checks (address, one problem, length, language, the middle step's bar, the judge) send the draft to the owner, who may send it anyway on the record. The judge still runs past a soft failure, so the owner always sees its verdict. | `test_verify.py::test_the_judge_runs_when_only_a_soft_check_failed_and_the_override_says_what_it_said`, `test_autonomy.py::test_an_override_never_beats_the_rules_do_not_contact_included`, `test_verify.py::test_a_hard_failure_blocks_an_owner_task_too` |
| **Human sign-off for high stakes** | The autonomy dial per action (`autonomy.MODES`: suggest, ask the owner, act alone). Weak evidence caps the dial at "ask the owner", and approving re-runs the owner's rules. **Gap:** every customer-facing action still defaults to "ask the owner"; the per-action defaults (money: ask, safe nudges: act alone) come in plan Step 3. | `test_autonomy.py::test_defaults_ask_the_owner_except_internal_tasks`, `test_autonomy.py::test_weak_evidence_caps_the_dial_at_ask_owner`, `test_autonomy.py::test_approval_rechecks_the_rules` |
| **Accept extra turns for accuracy** | A failed draft costs another turn, not a lower bar. In the recorded live run, 12 decisions took 22 drafts (10 retries) and one went to the owner rather than out. Decisions run at effort medium (triage low, rule compiling high). | `test_app.py::test_replay_serves_mayas_recorded_live_run` (drafts > decisions; the held draft), `test_verify.py::test_a_claim_the_judge_rejects_goes_back_and_the_next_draft_passes` |
| **Separate builder and read-only reviewer sessions** | At run time: the judge is a different model (Muse Spark Open) from the builder (Muse Spark 1.3). It has no tools and reads only the claims and the facts the draft cites. In the build: review passes ran as separate sessions and landed as their own commits ("Review fixes...", 29 Oct). **Gap:** nothing in the tooling enforces the build-time split; it is a habit, not a check. | `test_verify.py::test_the_judge_gets_claims_and_only_the_cited_facts`, `test_verify.py::test_the_judge_always_sees_the_message_first_and_never_part_of_a_draft` |
